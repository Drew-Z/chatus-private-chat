# Legacy Cleanup Readiness Audit

This audit records current-state evidence for legacy and rollback surfaces. It is intentionally non-destructive: no storage, Durable Object data, runtime route, or user-owned history is deleted by this task.

## Summary

- No production-facing legacy surface is safe to delete immediately.
- Most cleanup depends on production acceptance for the React/Agent workspace and typed admin surface.
- `UserState` is not only legacy chat storage. It still owns login throttling, quota compatibility, guest turn leases, health evidence, and migration input.
- Cloudflare Durable Object migration tags are deployment history and must not be edited for cleanup.

## Follow-Up Task Recommendations

1. Close the React/Agent and typed admin production acceptance window before deleting rollback routes or static assets.
2. Build a sanitized migration-status report for chat, memory, hidden credential markers, and inline legacy routes before any runtime deletion.
3. Split `UserState` responsibilities into an ownership map before treating any method or storage table as removable legacy.
4. Keep provider health passive. Cleanup tasks must not introduce Cron, doctor, background completion, or hidden synthetic prompts.
