# Capability Experience And Monitoring Design

## Member Information Architecture

The conversation inspector gains one Capabilities section with Workflows, Turn
tools, Image understanding, and Connections subsections. Detailed disclosure and
setup state live there. Attachment, explicit next-turn research, and send remain
in the composer. Message parts retain visible tool/citation progress and results.

Ephemeral waiting/running state is not saved to localStorage, Agent messages,
export, or Provider evidence. Failed sends restore a submitted draft only when no
newer draft generation exists. Exact server projections are the sole source of
capability truth.

## Administrator Information Architecture

The existing capability/admin operations surfaces show catalog installation,
origin, activation, affected data classes, helper/search assignment and
readiness, plus content-free outcome summaries. Revision conflicts preserve the
local draft and expose the current server version.

## Aggregate Ownership

Document whether the existing model-monitoring aggregate can store complete
hourly orchestration counters while keeping Provider attempts physical-call
only. Reuse it if so. Otherwise introduce the smallest bounded owner; a new
Durable Object is last resort and requires binding/migration, retention,
capture/restore, readiness, packaging, and local tests. Monitoring writes are
best-effort and projections mark stale or unavailable evidence.

## Responsive And Accessible States

Controls have stable dimensions, familiar icons and tooltips, semantic labels,
visible focus, at least existing-system touch targets, restrained live-region
updates, reduced-motion support, and no horizontal overflow. Desktop, compact
desktop/tablet, phone, and touch-phone fixtures cover setup, active, failure, and
recovery states.

## Rollback

Hide enhanced capability panels and disable aggregate read/write. Catalog,
vision, research, Provider monitoring, and chat routing remain independently
usable.
