# Explicit Web Research Design

## Activation And Binding

The composer requests a bounded capability ID for the next turn. The server
rechecks assignment, availability, connection, review, and the shared three-Skill
limit immediately before I/O. A web-search role can bind only to a reviewed,
enabled, read-only MCP tool with one bounded `query` input and compatible exact
result schema.

## Execution And Citations

Chatus invokes the MCP tool before main Provider construction regardless of the
selected route's tool support. The latest user text is the disclosed query. The
adapter accepts only an exact versioned JSON text block, sanitizes at most ten
public HTTPS results, bounds total data, deduplicates canonical URLs, and
preserves order. The Provider receives a numbered normalized block; Agent and
transitional output retain matching normalized citation metadata for UI links.

## Errors And Privacy

Denial, connection loss, review drift, timeout, cancellation, malformed or empty
results stop the research path. Raw MCP bodies, unbounded snippets, credentials,
and query text never enter capability monitoring. Current MCP SSRF, OAuth,
approval, fingerprint, timeout, size, and close rules remain authoritative.

## Rollback

Disabling or unbinding the catalog item removes the per-turn control and makes
stale requests fail before MCP I/O. Generic model-initiated MCP tools keep their
existing behavior.
